# Ultrasound QC Engine — 离线超声报告自动勘误与质控引擎

轻量级本地质控引擎（**v1.2.3**）：读取 `rules.json` 规则库，对超声报告执行 9 类质控规则检查
（描述与结论不一致 / 分级不规范 / 语病或表述不规范 / 数据或单位错误 / 错别字或字段缺失 /
模板文字未删除 / 遗漏检查部位 / 其他 / 性别年龄冲突）。输入支持**标准 JSON 报告对象**（工作站集成规范）
与报告文本（兼容旧版 PACS 导出）。
**纯 Python 标准库实现，零第三方依赖、零外网、零 GPU**，可打包为单文件 exe 部署于医院老旧
Windows 电脑（Win7/Win10，32/64 位），供 PACS/报告系统对接。

| 指标         | 表现                                        |
| ------------ | ------------------------------------------- |
| 单份报告耗时 | 约 0.1~0.3 ms（1000 份实测）                |
| 运行内存     | < 20 MB（无 pandas/numpy，exe 仅约 8.5 MB） |
| 外部依赖     | 无（Excel 导出为内置迷你 xlsx 写入器）      |

## Web 端数据纠错系统

仓库内 `webapp/` 提供可部署到 Linux 服务器的完整 Web 端数据纠错系统（前后端分离）：
文件上传解析（txt/json/csv/tsv/xlsx，支持一次上传多个文件合并纠错）、一键纠错与实时状态提示、问题逐条定位与修改建议、
纠错结果一键导出 Excel（质控概览 + 错误明细）、8 组免上传预置测试数据集、一键部署脚本（systemd/nginx）。
使用与部署详见 **[webapp/README.md](webapp/README.md)**。

## 1. 快速开始

### 1.1 内置自检（部署后首先执行）

```bash
python qc_engine.py selftest        # 或双击运行: UltrasoundQCEngine-CLI.exe selftest
```

26 个内置用例覆盖 9 类质控规则与标准 JSON 输入，全部输出 PASS 即部署正常。

### 1.2 命令行批量检测

```bash
# 检测单个文件 / 整个目录（目录默认扫描全部 .txt）
python qc_engine.py check report.txt
python qc_engine.py check D:\reports -o D:\out\qc_result.xlsx

# 同时输出每份报告的 JSON 明细（便于调试）
python qc_engine.py check D:\reports --json
```

结果导出为 Excel（两个 Sheet：`质控概览` + `错误明细`），双击即可查看。

### 1.3 HTTP API 服务（PACS 实时对接）

```bash
python qc_engine.py serve --host 0.0.0.0 --port 8976
# 可选：--token mysecret  （启用后所有请求需带请求头 X-Auth-Token: mysecret）
```

### 1.4 两种 exe 的分工

| 文件                         | 窗口     | 用途                                                               |
| ---------------------------- | -------- | ------------------------------------------------------------------ |
| `UltrasoundQCEngine.exe`     | 无控制台 | 常驻 HTTP 服务、开机自启；控制台输出重定向到同目录 `qc_engine.log` |
| `UltrasoundQCEngine-CLI.exe` | 控制台   | 人工批量检测，可看到实时输出                                       |

### 1.5 部署目录结构（交付包解压后）

```text
UltrasoundQCEngine-v1.1.0/
├── README.md                  # 本使用说明
├── rules.json                 # 规则库（必须与 exe 同目录，现场修改重启即生效）
├── UltrasoundQCEngine.exe     # 常驻 HTTP 服务（无控制台）
├── UltrasoundQCEngine-CLI.exe # 命令行批量检测（有控制台）
└── source/                    # 源码与工具（Python 3.8+ 标准库即可运行，不打包也无影响）
    ├── qc_engine.py           # 引擎完整源码
    ├── build_exe.py           # PyInstaller 打包脚本
    ├── extract_rules.py       # 规则提炼脚本
    └── blind_test.py          # 盲测对比工具（需 pandas 与数据集，可选）
```

> 医院部署只需 exe + rules.json 两个文件放在同一目录即可运行；若 `rules.json` 缺失，
> 引擎自动加载内置默认规则。若需从源码运行，把 `source/` 内文件与 `rules.json`
> 放同一目录后执行 `python qc_engine.py selftest` 验证。

## 2. HTTP API 文档

### POST /api/check — 单份报告质检

请求体为**标准 JSON 报告对象**（工作站集成规范，核心字段：检查项目/性别/年龄/超声所见/超声提示）：

```json
{
  "exam_item": "肝胆胰脾彩超",
  "gender": "男",
  "age": "50",
  "finding": "肝脏形态大小正常，包膜光滑，实质回声均匀。",
  "conclusion": "肝胆胰脾未见明显异常。"
}
```

亦支持中文键名（`检查项目/性别/年龄/超声所见/超声提示`）、`{"report": {...}}` 包装，
以及旧版 `{"text": "报告全文"}` 或纯文本（Content-Type: text/plain，编码 UTF-8 或 GBK 自动识别）。

响应（200）：

```json
{
  "ok": true,
  "engine_version": "1.1.0",
  "input_format": "json",
  "report": { "exam_item": "肝胆胰脾彩超", "gender": "男", "age": "50" },
  "parsed": {
    "finding": "...",
    "conclusion": "...",
    "parse_notes": ["标准 JSON 输入"]
  },
  "issues": [
    {
      "rule_id": "遗漏检查部位",
      "rule": "遗漏检查部位",
      "error_type": "遗漏检查部位",
      "severity": "high",
      "field": "finding",
      "fragment": "肝脏形态大小正常，包膜光滑，实质回声均匀。",
      "message": "检查项目“肝胆胰脾”应检查部位（肝、胆、胰、脾），但超声所见中缺少胆、胰、脾的描述，所见遗漏检查部位",
      "suggestion": "请补充胆、胰、脾的超声所见描述，确保检查项目要求的部位逐一记录"
    }
  ],
  "issue_count": 1,
  "elapsed_ms": 0.12
}
```

`issues` 为结构化错误提示数组，工作站前端可直接解析弹窗/高亮：`rule_id`（错误类型名，与质控 Excel「错误类型」列一致，同时作为规则归类）、
`rule`/`error_type`（同 rule_id，三者统一）、`severity`（high/medium）、`field`（问题字段）、`fragment`（原文片段）、
`message`（问题描述）、`suggestion`（修改建议）。

### POST /api/check/batch — 批量质检

```json
{ "reports": [ { "exam_item": "...", "finding": "...", "conclusion": "..." }, ... ] }
```

或旧版 `{"texts": ["报告1全文", "报告2全文"]}`。

### 其他端点

| 方法 | 路径         | 说明                                         |
| ---- | ------------ | -------------------------------------------- |
| GET  | `/health`    | 存活探针（PACS 轮询用）                      |
| GET  | `/api/rules` | 查看当前生效规则（敏感词/纠错映射/分级规则） |
| GET  | `/`          | 简易使用说明页                               |

**curl 调用示例**（PowerShell）：

```powershell
curl.exe -s -X POST -H "Content-Type: application/json" --data-binary "@body.json" http://127.0.0.1:8976/api/check
```

## 3. 质控规则说明

| 规则 | 名称               | 逻辑                                                                                                                                                                                                                                     | 严重度      |
| ---- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| A    | 结论遗漏病变       | 所见含**强病灶词**（结节/囊肿/占位/结石/钙化等实体词），结论却为纯阴性表述（"未见明显异常"等）。内置子句级否定识别（"未见结节""血流信号正常""管壁不增厚"均不误报）；结论以等价表述呼应（如"斑块→动脉粥样硬化性改变""结节→低回声"）时不报 | high        |
| B    | 左右侧不符         | 所见与结论中**同一器官**左右侧冲突（如所见"左乳结节"结论"右乳结节"）；器官归一化支持"附睾头部→附睾""左叶甲状腺→甲状腺""腋窝淋巴结→淋巴结"等写法                                                                                          | high        |
| C    | 用词勘误           | 命中 `correction_mapping`（如 回音→回声、股径→股骨长），给出替换建议                                                                                                                                                                     | medium      |
| D    | 分级冲突           | ①所见与结论分级号不一致；②乳腺所见含微钙化/边界不清/形态不规则/毛刺等征象但 BI-RADS 分级偏低（如 2 类）；③胎盘成熟度写法非标准 Grannum 分级（如"Ⅱ+级"）                                                                                  | high/medium |
| E    | 结论未涵盖所见     | 所见病灶/特殊征象在结论中无任何等价呼应（如见"结节"结论只字未提）。带测量值回声病灶、血流充盈缺损、左室舒张功能减低依据（E峰<A峰）均纳入；产前/胎儿报告豁免；条索/分隔等结构描述及病灶伴随特征不单独要求                                 | high        |
| F    | 完整性与书写规范   | ①建议语缺时间数值（"建议周后复查"→"建议3周后"）；②数值粘连（"1.01.27"）；③检查项目与内容不符（产科项目无胎儿内容/妇科项目出现胎儿内容，产后流产后豁免）                                                                                  | medium      |
| G    | 性别与检查项目冲突 | 患者性别与检查项目/所见部位矛盾：男见子宫/卵巢/附件/乳腺等、女见前列腺等（器官词表可配置，乳腺等可按院内要求增删；男性乳腺/两性畸形等豁免）                                                                                              | high        |
| H    | 所见遗漏检查部位   | 检查项目要求多个部位（如肝胆胰脾），超声所见只描述了其中一部分（如仅肝脏）→ 报出缺失部位（胆、胰、脾）。器官别名与项目-部位映射可配置；仅"部分描述、部分缺失"时触发，单部位项目不误报                                                    | high        |

**标准 JSON 输入**（工作站集成规范）：`POST /api/check` 直接接收
`{"exam_item":"检查项目","gender":"性别","age":"年龄","finding":"超声所见","conclusion":"超声提示"}`，
字段别名兼容中文键名与 examItem/finding/conclusion 等常见写法，无需正则猜测格式。
命令行 .txt 批量检测与旧版 `{"text":...}` 提交仍走文本自适应解析：自动识别中英文标签
（`超声所见/提示/结论/印象` 与 `examItem/finding/conclusion/gender/age`），
兼容"标签：内容"行内式与逐行式；自动截断"知情同意/声明"等模板尾段；GBK/UTF-8/UTF-16 编码自适应。
解析失败时不报错，降级为"全文按所见处理"并写入 `parse_notes`。

**盲测验证**（`blind_test.py`：从 1000 份中固定种子抽样 100 份，与大模型质控结果做报告级对比，可复现）：

| 阶段                    | 查准率 P | 查全率 R | F1        | 说明                  |
| ----------------------- | -------- | -------- | --------- | --------------------- |
| 仅 A/B/C/D（基线）      | 100%     | 4%       | —         | 无 E/F 规则，大量漏报 |
| E/F 首版                | 25.3%    | 76%      | —         | 误报 56 条            |
| **A~F 精细化**          | **100%** | **32%**  | **48.5%** | TP=8，FP=0            |
| **A~H + JSON/解析修复** | **100%** | **32%**  | **48.5%** | TP=8，FP=0（无回归）  |

全量 1000 份复核：**P=78.0%、R=25.5%、F1=38.4%**（TP=64、FP=18，单份 0.1ms；
规则 G 零误报，规则 H 精准命中"泌尿系缺膀胱"等真实漏项）。

迭代方法：盲测 100 份发现 FP/FN 模式 → 全量 1000 份口径仲裁（大模型对同模板判定不一致时以全量多数为准）
→ FP 精细化正则与结论等价表述、FN 向 `rules.json` 补词补映射（改文件即生效，免重编译）。

**范围外口径**（大模型判定而引擎按设计不覆盖）：孕周与测量值核算、语病与措辞风格、
分级标准分歧（C-TIRADS / BI-RADS 类别争议）、血管分段清单逐支比对、检查项目缺失口径、
肠气干扰"显示不清"省略惯例。

## 4. rules.json 规则库

引擎按以下顺序查找规则：`--rules` 参数 → exe 同目录 `rules.json` → 内置默认规则。
**rules.json 不打包进 exe**，医院现场可直接改文件调规则，无需重新编译：

```json
{
  "positive_keywords": ["结节", "囊肿", "..."],
  "correction_mapping": { "回音": "回声" },
  "negative_conclusion_phrases": ["未见明显异常", "..."],
  "grading_rules": {
    "min_grade_features": { "微钙化": 4 },
    "context_keywords": ["乳腺"]
  },
  "gender_conflict": {
    "male_organs": ["前列腺", "..."],
    "female_organs": ["子宫", "卵巢", "附件", "乳腺", "..."],
    "exempt_keywords": ["男性乳腺", "..."]
  },
  "exam_organ_map": {
    "organ_aliases": { "肝": ["肝", "肝脏"], "胆": ["胆", "胆囊"] },
    "exam_items": [{ "exam": ["肝胆胰脾"], "organs": ["肝", "胆", "胰", "脾"] }]
  }
}
```

`positive_keywords`/`side_keywords` 同时兼容 `["词"]` 与 `[{"word":"词","count":n}]` 两种格式，
可直接使用 `extract_rules.py`（大模型质控结果提炼脚本）的产出，形成
**大模型提炼规则 → 离线引擎执行** 的闭环。改完规则重启服务即生效。

## 5. 打包为 exe

```bash
python build_exe.py                  # 同时产出无控制台版 + 控制台版
python build_exe.py --console-only   # 仅控制台版
python build_exe.py --icon logo.ico  # 自定义图标
```

脚本自动安装 PyInstaller 并排除 pandas/numpy 等无关大件。

**老旧系统兼容要点（重要）**：

- PyInstaller 不支持跨平台/跨位数打包：**目标机是 Win7 或 32 位系统时，必须在同类环境打包**。
- 推荐组合：`32 位 Python 3.8.10`（官方支持 Win7 的最后版本）+ `pip install pyinstaller==5.13.2`，
  在 Win7/32 位机器（或虚拟机）上执行 `python build_exe.py`，产物即可在同类老旧系统运行。
- Win10 64 位目标机可直接用新版 Python 3.11+ + 最新 PyInstaller 打包。

## 6. 老旧 PACS 系统对接建议

1. **通信编码**：老 PACS 多用 GBK 发送 HTTP 正文，引擎已自动识别（UTF-8 → GB18030 → UTF-16），
   无需对方改造；建议响应按 UTF-8 解析。
2. **部署位置**：引擎与 PACS 同机部署时监听 `127.0.0.1` 即可（更安全）；跨机部署用
   `--host 0.0.0.0` 并在 Windows 防火墙放行对应端口（入站规则 → 端口 → TCP 8976）。
3. **开机自启（免安装方案）**：
   - 计划任务：任务计划程序 → 创建任务 → 触发器"登录时/启动时" → 操作
     `D:\qc\UltrasoundQCEngine.exe serve --host 0.0.0.0 --port 8976`；
   - 或使用 NSSM 将其注册为 Windows 服务（支持崩溃自动重启）。
4. **调用模式**：
   - **实时模式**：报告保存事件触发 PACS 调 `POST /api/check`，解析 `issues` 即时提示医生；
   - **轮询模式**：老 PACS 无法改造时，用共享目录+定时脚本调用 CLI 版扫描新报告并写回 Excel。
5. **健康监控**：PACS 侧定期 `GET /health`；进程异常退出时配合计划任务/NSSM 自动拉起。
6. **安全**：公网/跨科室网络暴露时务必加 `--token` 并保持内网隔离；引擎无鉴权体系，
   不应直接暴露到院外网络。
7. **杀毒软件**：PyInstaller 单文件 exe 偶发被误报，将部署目录加入白名单，
   或改用"目录版"打包（去掉 `--onefile`）。
8. **资源占用**：进程内存 < 20MB，CPU 毫秒级，老旧电脑可长期常驻；onefile 首次启动
   需解压到临时目录（约 1 秒），对实时调用无影响。

## 7. 常见问题

| 现象                        | 处理                                                              |
| --------------------------- | ----------------------------------------------------------------- | -------------------------- |
| 无控制台 exe 双击后"没反应" | 属正常（后台运行）；查看同目录 `qc_engine.log`，或用 CLI 版排查   |
| 端口被占用                  | `--port` 换端口；或 `netstat -ano                                 | findstr 8976` 找到占用进程 |
| 报告乱码                    | 已自动识别编码；如仍异常，确认文件未被加密/整段为图片             |
| 想临时关闭某条规则          | 编辑 rules.json：清空对应词表（如 correction_mapping 置空）后重启 |
| 批量扫描包含子目录          | 当前仅扫描目录第一层 .txt；如需递归可循环传入多个目录             |
